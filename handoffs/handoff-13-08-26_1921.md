## Gotchas discovered this session

- **A gate whose window ends "today" blocks every matchday evening.** ESPN flips a fixture to finished at full time; the canonical is only rebuilt at 06:00 (ADR 0006). Measured against the EFL final day, a gate run that evening would have demanded **12 fixtures that could not yet exist**. Fixed with `PUBLISH_GRACE_DAYS = 2`. **Two, not one**, because the gate reasons in dates, not hours — a dashboard scan at 03:00 precedes that morning's ingest.
- **Cache the fetch, never the verdict.** A cached STALE keeps betting blocked after the operator fixes the data, making "restart the dashboard" the folk remedy. Caching only the authority fetch keeps the canonical re-read every call. Saving is real: 3.7s → 0.1s on the redundant check.
- **A module-level cache made the test suite pass on stale evidence** — a freshness gate whose own tests had a freshness bug. The autouse `clear_cache()` fixture in `tests/test_freshness.py` is load-bearing, not hygiene.
- **`except SomeError` is unverified until something raises.** `scan.py` needed a top-level `from freshness import FreshnessError`; without it the handler would have `NameError`d at exactly the moment the gate first fired.
- **`normalize()` answers in PL long-form only.** It scores 20/20 on PL and **0/24** on EFL against football-data.org names. `resolve_feed_team` handles 21/24 EFL unaided; the three abbreviations (QPR, Sheffield Weds, West Brom) are in `_FOOTBALL_DATA_TO_CHAMP`. This is ADR 0008's documented failure mode, one feed further on.
- **`scan.py:474`/`487` retrain inline** when `load_trained_state()` fails — a matchday scan is a Data Refresh, which ADR 0005 did not anticipate. Three train sites, not one.
- **`grep -r` from the project root still times out on OneDrive.** Hit it again despite the previous handoff's warning. Use the Grep tool with a `glob` filter.
- **Python printing to console still dies on cp1252** for `→` and `—`. Use the Read tool or set `PYTHONIOENCODING=utf-8`.
- The full suite now takes **~17 minutes**. Run it in the background; **trust the pytest summary line, never the exit status** (the 04-08 handoff's warning — the exit code was honest this time, but the check is still what makes that knowable).
