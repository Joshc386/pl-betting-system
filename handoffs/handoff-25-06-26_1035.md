## RESUME HERE — the OddsPapi exchange-coverage probe (next session focus)

The user confirmed: **next session we probe OddsPapi to see if it already solves live Matchbook + Betfair odds.** This is Step 1 of the roadmap and likely collapses most of the work.

**Why this matters:** the user pointed to `oddspapi.io/blog/matchbook-api-uk-exchange-odds/`. OddsPapi's `/odds` returns `matchbook`, `betfair-ex`, and `pinnacle` in one response with full `availableToBack`/`availableToLay` ladders + `size` (liquidity). And our code is already positioned to receive them:
- `betfair-ex` is **already** in `ODDSPAPI_TIER1_BOOKS` ([config.py:656](config.py:656)).
- The `/odds` call sends **no `bookmakers` filter** — `_api_get("/odds", {"fixtureId": ...})` ([api/oddspapi.py:507](api/oddspapi.py:507)) returns all books; parsers iterate `bookmaker_odds.items()` generically. So Matchbook/Betfair-ex keys already flow through if present.

**The probe (read-only, ~1 OddsPapi credit, no writes, no bets):**
1. Use the existing `ODDSPAPI_KEY` (in `.env`). Pick one upcoming PL fixture (`get_fixtures` in `api/oddspapi.py`).
2. Fetch `/odds` for it and inspect whether `matchbook` and `betfair-ex` appear under **O/U 2.5, alt O/U lines, and BTTS** (not just Moneyline — the blog only demoed market 101).
3. Check whether `exchangeMeta` / `availableToBack`/`availableToLay` (+ `size`) is present in the raw response (the current parsers likely take a single price and drop liquidity).

**Decision gate:**
- **If covered** → scrap the direct Matchbook/Betfair connectors entirely. Remaining work shrinks to: add `"matchbook"` to the recognised-book config set (alongside `betfair-ex`); optionally capture `exchangeMeta` liquidity for exchange sources; surface per the exchange spec. **No new auth, no Matchbook credentials needed.**
- **If coverage too thin for our markets** → fall back to a direct connector. Matchbook API recon already done this session (no credentials were ever added): `POST https://api.matchbook.com/bpapi/rest/security/session` `{username,password}` → `session-token` header, ~6h session; bulk live odds via `GET https://api.matchbook.com/edge/rest/events?sport-ids=<soccer>&include-prices=true&states=open`; soccer `sport-id` and O/U-vs-BTTS `market-type` strings still unknown (discover via authenticated probe). Betfair would use its own Python lib. **Prefer the OddsPapi path if it works.**

**Caveats:** OddsPapi is the **250/month** quota and is currently **gated off by default** in scans (`DASHBOARD_FETCH_ODDSPAPI=False`); going live on exchange odds means enabling it and spending against that cap (the #4/#5 quota-guardrail work supports this). Coverage tracks where Matchbook has real liquidity — niche fixtures return an empty book (expected).
