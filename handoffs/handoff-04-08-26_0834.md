## Gotchas discovered this session

- **A guard that compares two frames by row *position* will fire falsely the moment row order changes.** The Facts guard refused the PL publish with "Date changed in 1172 rows" then "Home_Team changed in 31" — both false, caused by the 46 preserved rows re-entering at different offsets. Fixed in `3cfc918` to merge on `(SeasonIndex, Home_Team, Away_Team)`. **Row order is not part of the canonical's contract.**
- **Betfair's `over_ltp` is in-play contaminated and would silently destroy any backtest using it.** Median 1.53 when the over won, **15.00** when it lost, 18% above 100. Only `*_ltp_first` is safe. `alt_lines_data.py:82` already knew this; the canonical now does too.
- **A 0% join rate is a naming bug; a 40-80% rate is a data gap.** Per-team match rates separated the two instantly — five EFL clubs at exactly 0% recovered 945 fixtures. A whole-league coverage number would have hidden it completely.
- **Betfair's `country_code=GB` feed contains worldwide events** (Romanian, Mauritanian clubs) and women's/youth/reserve fixtures under near-identical names. Both must be filtered explicitly.
- **The enriched CSV must be rebuilt after every canonical change** — `pipeline.py:32` prefers it, so a stale enriched silently starves new columns. Caught twice this session (ADR 0004's "one canonical artefact" is still unresolved).
- **The date rolled over mid-session.** Six doc references were written as 08-02 when the work was 08-03; corrected in `df11b71`. Verify against `git log --date` rather than assuming.
- **OneDrive makes repo-wide `grep`/`glob` time out.** Use the Grep tool with a `glob` filter, never `grep -r` from the project root.
- The full suite takes **15–35 minutes**. Run it in the background, and confirm it actually completed.
