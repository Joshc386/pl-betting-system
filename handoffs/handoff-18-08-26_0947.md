## 1. The weekly retrain — cause proven, Phase 1 BUILT, retrain running

**Diagnosed from the Windows event log 2026-08-18. Not a code bug and not a task
misconfiguration: the machine slept underneath the job.**

```
07:51:20  Task Scheduler launches the task (StartWhenAvailable catch-up from Sun 23:30)
08:09:46  Kernel-Power 506 — "The system is entering Modern Standby"   <- 18 min in
08:16:17  Kernel-Power 507 — "The system is exiting Modern Standby"
08:16:20  weekly_retrain_20260817.log writes its last line, then ^C
08:17:56  process exits 0xC000013A (STATUS_CONTROL_C_EXIT)
```

Modern Standby (S0 low-power idle) suspended a long-running console process and the
console session tore down across the resume. It survived resume by ~90 seconds.

**Two findings that change what "fixing it" means:**

- **`WakeToRun` is irrelevant.** The machine was awake when the task started; it fell
  asleep mid-job. Setting `WakeToRun` would not have helped.
- **`RestartCount: 3` is not a safety net here.** Task Scheduler logged event **201,
  "successfully completed"** — a non-zero *exit code* is not a task failure, so no retry
  fired. The task's own history shows a green-looking run for a job that died.

**Nothing noticed for two days,** and only then because the user asked an unrelated
question about running the system without Claude. This is
[ADR 0006](docs/adr/0006-task-scheduler-for-data-critical-jobs.md)'s recorded blind spot
repeating — that ADR's correction says it "never asked what would notice if a catch-up
did not happen", and the answer is still nothing.

**Consequence:** both `pl_trained_state.pkl` and `efl_trained_state.pkl` are **8.0 days
old**, past the 7-day threshold.

## 2. PL promoted teams produce no predictions — confirmed, root cause known

The user reports **every market on PL fixtures involving promoted teams has no
prediction, and that this is PL-only.** That is exactly the behaviour identified in the
previous session and deliberately scoped out of
[ADR 0011](docs/adr/0011-one-division-movement-seed-per-arrival.md); the symptom
confirms the diagnosis rather than adding to it.

**Root cause:** `predict.py:983` — when either side has no row in the current season,
the fixture is skipped outright:

```python
if len(home_rows) == 0 or len(away_rows) == 0:
    self._log(f"Skipping {home_mapped} vs {away_mapped} (no recent data)")
    continue
```

`latest_df` is scoped to the current season (`predict.py:962`), so the three sides
promoted for 2026/27 — **Coventry, Hull, Ipswich**, each with 0 rows in PL S25 —
match that branch on every market.

**Why PL-only:** the EFL has `_synthesize_promoted_fixture`; the PL never got an
equivalent. ADR 0011's Consequences section records this asymmetry and leaves it as
separate work.

**Do not simply port the EFL synthesis.** ADR 0011 measured why: the pre-ADR EFL
synthesis used a league *median*, which overstates `Over25_5` by 16 points for a side
that is by construction one of the division's weakest. The EFL now seeds from a route
cohort via `division_movement.seed_features`, which is the thing worth porting — and
`division_movement.py` is already league-agnostic in shape, though `arrival_route`
assumes the sibling frame is the division above.

**Also still true and unexploited:** Coventry, Hull and Ipswich each have **46 rows in
the EFL canonical's latest season**, and `pipeline.py` contains no cross-league read at
all. Full reasoning in the previous block.
