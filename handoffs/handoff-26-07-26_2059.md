## Gotchas discovered this session

- **`python api/foo.py` fails where `python -m api.foo` works.** Running a file directly puts its own directory on `sys.path`, not the project root, so `from api.x import y` cannot resolve.
- **A partially-staged index survives between sessions.** The builder rename was already `git add`ed by the morning session, so a `git commit` after staging unrelated files silently swept it in. Check `git diff --cached --stat` before committing in any session inheriting a dirty tree.
- **football-data.co.uk genuinely serves only 335 rows for `E0` seasons 3-4.** Verified against `Content-Length` — an upstream gap, not a truncated download. `soccerdata` cannot help; it reads the same file.
- **The builder writes raw bytes to cache but reads them as UTF-8.** `E0_0405.csv` contains byte `0xa0` and cannot be re-read from cache; the `except Exception: pass` swallows it and silently re-downloads every build.
- **Rate limiting is real.** 26 back-to-back season downloads triggered `503`s minutes later.
- **`pytest.mark.xfail(strict=True)` is the right tool for a known-broken-until-fixed state.** It XPASSed the instant the data was repaired, failing the suite and forcing its own removal rather than lingering as a stale exemption.
